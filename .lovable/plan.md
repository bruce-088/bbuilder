## Goal

Give Mya a first-class `generate_pdf` skill so users can say "make me a PDF of this plan / proposal / outreach script" in chat and get an actual PDF download — without leaving the conversation.

## Approach: client-side rendering via a chat tool

Mya already runs against the LLM with a `COPILOT_TOOLS` registry in `supabase/functions/chat/index.ts` (~18 tools). All existing tools execute server-side. PDF generation is the first tool that needs the **browser** to do the work (jsPDF lives in `src/lib/pdfGenerator.ts` and runs client-side).

So we add `generate_pdf` as a "client-resolved" tool:

1. **Edge function** declares the tool in `COPILOT_TOOLS` but does NOT execute it. When the LLM emits a `generate_pdf` tool call, the edge function returns it to the frontend untouched (as part of the assistant message's `tool_calls`), and feeds a synthetic tool result back (`"Delivered to user as a PDF download"`) so the model can continue naturally.
2. **Frontend** (`src/pages/Chat.tsx`) inspects assistant messages for `tool_calls` named `generate_pdf`, builds the PDF with a new shared helper, triggers the download, and renders a small "📄 Downloaded: filename.pdf" chip inline with the message.

This keeps secrets/services out of the loop, avoids a new edge function, and gives instant downloads.

## Implementation

### 1. Shared helper — `src/lib/myaPdfGenerator.ts` (new)

A single function `generateMyaPdf({ title, subtitle?, sections, filename })`:

- `sections: Array<{ heading?: string; body: string }>` — body is Markdown-lite (paragraphs, bullets `- `, numbered lists, `**bold**`).
- Uses `jsPDF` (already a dependency).
- Brand: Emerald `#10b981` accents, dark heading color, Inter-ish system font, footer "Generated by Mya · {date}" + page numbers.
- Word-wrap, auto page-break, max ~50 pages safety cap.
- Returns `{ blob, filename }`; caller triggers download via object URL + `<a download>`.

This is reusable by other surfaces later (Plans page, Strategy page) — replaces ad-hoc generators over time.

### 2. Tool declaration in `supabase/functions/chat/index.ts`

Append to `COPILOT_TOOLS`:

```ts
{
  type: "function",
  function: {
    name: "generate_pdf",
    description:
      "Generate a downloadable PDF document for the user (business plan, proposal, outreach script, summary, etc.). Use whenever the user asks for a PDF, document, printable, or downloadable file. The PDF is rendered in the user's browser and downloaded immediately.",
    parameters: {
      type: "object",
      properties: {
        title:    { type: "string", description: "Main title shown on the cover/first page" },
        subtitle: { type: "string", description: "Optional subtitle / tagline" },
        filename: { type: "string", description: "Filename without extension, kebab-case (e.g. 'q1-outreach-plan')" },
        sections: {
          type: "array",
          description: "Ordered sections rendered top-to-bottom",
          items: {
            type: "object",
            properties: {
              heading: { type: "string" },
              body:    { type: "string", description: "Markdown-lite: paragraphs, '- ' bullets, '**bold**'" }
            },
            required: ["body"]
          }
        }
      },
      required: ["title", "sections", "filename"]
    }
  }
}
```

### 3. Dispatcher change in `supabase/functions/chat/index.ts`

In the existing `switch (toolCall.function.name)` block, add:

```ts
case "generate_pdf": {
  // Client-resolved: pass args through so the frontend can render.
  clientToolCalls.push({
    id: toolCall.id,
    name: "generate_pdf",
    args: parsedArgs,
  });
  return "Delivered to the user as a PDF download.";
}
```

Return `clientToolCalls` alongside the assistant response so the frontend can act on it. (Touch the existing response shape minimally — add an optional `client_actions` field.)

### 4. Frontend handler in `src/pages/Chat.tsx`

When a chat response includes `client_actions` with a `generate_pdf` entry:

- Call `generateMyaPdf(args)`, trigger download, toast "📄 {filename}.pdf downloaded".
- Persist a marker on the assistant message (e.g. `metadata.attachments: [{ kind: 'pdf', filename }]`) so the rendered bubble shows a clickable "📄 filename.pdf" chip. Re-clicking the chip re-generates from the stored args (kept in component state for the session — no DB schema change needed).

### 5. System prompt nudge

Add one line near the existing Mya persona in `supabase/functions/chat/index.ts`:

> "When the user asks for a PDF, document, printable, downloadable file, or 'send me this in writing', call `generate_pdf` with well-structured sections — don't paste a long document in chat."

### 6. Files touched

- **Create**: `src/lib/myaPdfGenerator.ts`
- **Edit**: `supabase/functions/chat/index.ts` (tool registration + dispatcher case + system-prompt line + response shape), `src/pages/Chat.tsx` (detect `client_actions`, run generator, render attachment chip).

## Non-goals

- No new edge function. No server-side PDF rendering.
- No DB persistence of generated PDFs (kept client-side for now). Easy to add later via Supabase Storage if needed.
- No changes to other existing tools.
